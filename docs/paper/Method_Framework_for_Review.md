# 方法与框架说明（供评审）

> **用途**：方法/框架设计文案，供评价设计质量与逻辑自洽。  
> **评价对象**：本文件陈述的**方法设计**。  
> **不是评价对象**：当前仓库某一时刻的代码完备度、未完成实验数字、本机账本条数。实现可后续补齐。  
> **刻意不包含**：网络条数、回路轮次、复用计数、phase 状态、账本条数、修订史、`auto_loop` 作为方法主角。  
> **口径来源**：`docs/paper/dialogue_change_ledger.md` §1；结构对齐 `Nature_Communications_Chinese_Outline_v4.md`。  
> **作者已确认口径**：  
> 1. 验收**只有**人类敲定的单一交付级标准。STRICT 只判反应边/路径；无 Skill/Tool patch「系统接纳」。  
> 2. 不讨论执行期内冻结/零演化的工程强制。  
> 3. **单一 agentic 主循环**；扩网 = 交付副产物；论文删除 `auto_loop`（非降级）。  
> 4. Graph 与专家确认交付包都是产出；交付包不回写 Graph。专家确认 ≠ 第二条验收门。  
> 5. 多样性轻量：搜索侧 **diversity-aware batch selection**（可称 QD-inspired，非主线）；不把 LLM 思维多样性写入形式化方法。  
> 6. 固定资产/关反思 = **评价条件/成果展示**，不是第二套方法。  
> **相对 R1→R2 评审**：统一状态语义；拆分假设/尝试/实现；修正 C1/C2 因果对照；删除 creativity 叙事。

**目标期刊：Nature Communications**

## 0. 评审应关注什么

1. 背景/动机是否清楚；  
2. 方法是否自洽且可操作：人定边界、主循环契约、两类记忆、可编辑资产面、唯一验收不变量、轻量多样性、成果展示评价条件；  
3. 背景 → 方法逻辑链；

5. 设计内部是否 overclaim。  
**不要**：以代码完备度否决设计；不要恢复双验收、`auto_loop`/路由、工程冻结强制、Skill patch 接纳。

## 1. 文稿定位与一句话主张

本文展示一个面向复杂水相反应空间、角色分解的自进化智能体系统：在研究者预先定义目标与验收标准后，系统以一套主循环——探索候选、量子化学验证、写入科学状态与经验记忆、修订可复用能力资产——组装通向多个目标产物的统一反应网络，并打包可专家确认的交付材料。网络扩张是该循环的**副产物**。

「自进化」范围明确：只演化 **Skills/Tools**；演化发生在主循环的**反思环节**；证据来自结构化 QM 执行反馈；修改作为**版本化程序性干预**自动落盘并留痕。边/路径是否进入验收网络，由**人类敲定的交付级 STRICT**判定——验收标准**不评判资产补丁**；资产价值由复用与对照检验。

**一句话主张**：在人定目标与交付级验收边界下，结构化 QM 失败被转化为可追溯的 Skills/Tools 修订，从而改变后续探索/验证行为；网络与交付路径是这一主循环的副产物。当演化收益趋于饱和后，固定资产并关闭反思，在前瞻任务上检验自主发现能力。

### 1.1 两条可证伪的方法主张

| 主张 | 算法接口 | 主终点 | 对照 | 失败条件 |
|---|---|---|---|---|
| **C1** 结构化 QM 反馈产生可追溯的程序性修订，并改变后续系统行为 | 修订记录 schema + 激活点（§5.2） | 目标失败模式下降或同预算下成功边比例上升 | **修复重放** + **迁移重放**（§9.1） | 修订后行为无变化 / 无法指认激活 / 仅触发例改善而无迁移 |
| **C2** 累积资产在固定科学验收标准下改善前瞻发现/交付 | 固定资产评价条件（§10） | 同一前瞻任务集上的交付/成功率 | **最终演化资产集 vs 初始资产集**；**两侧评价时均冻结**；定向消融仅支持性分析 | 前瞻任务无增益 / 演化期任务泄漏进前瞻集 |

统一网络与专家确认交付包是上述主张的**产出/能力**，不另列独立方法贡献。

## 2. 核心贡献（方法向；两条）

1. **QM 反馈驱动、边界收紧的程序性资产演化闭环**  
   单一主循环将探索、验证、记忆与反思修订串起来；演化对象仅 Skills/Tools；人类敲定的 STRICT 只锚定边/路径质量；每次修订是带证据与版本谱系的自动落盘干预（非 patch 接纳门）。

2. **可审计的化学实例化：状态—修订—交付证据链**  
   Graph/Experience 分置科学状态与经验；写入矩阵明确；验收投影与专家确认交付包均为产出且不回灌 Graph；支持「先修订、后复用」的可追溯检验与前瞻成果展示。

## 3. 背景与动机

### 3.1 发现难题

葡萄糖通向 HMF、HAA、糠醛涉及多类基元事件；难点是让候选在同一网络中具有来源、可验证终点与可继续扩展的几何/结构状态。传统工作流将规划、猜测、IRC、证据整理分离，失败难跨任务累积。

### 3.2 缺口

拓扑可行但 QM 连不上；缺反应类型适配；经验未转化为能力更新；近重复浪费预算；多目标碎片化；证据链断裂。

### 3.3 方法回答

| 缺口 | 方法回应 |
|---|---|
| 经验难累积 | Experience + 版本化修订 Skills/Tools |
| QM 连不上 | Graph 存端点/失败；扩展前沿上扩展 |
| 缺类型适配 | 限定可编辑面内的规则/参数/模板/例程组合 |
| 自评分不可靠 | 人类敲定 STRICT 判边/路径 |
| 近重复 | 搜索侧 diversity-aware 选批（非主线） |
| 碎片化 | 统一 Graph |
| 证据断裂 | 验收投影 + 专家确认交付包（确认≠验收） |
| 名不副实多智能体 | 角色分解智能体系统 |
| 扩网与交付割裂 | 扩网 = 主循环副产物 |

科学对象边界（物种可比性）在 Methods 中固定环境假设：质子化态、溶剂/催化水政策、电荷、溶剂化处理、构象等价规则——正文方法主张假定这些假设已预注册。

## 4. 概念定位与单一验收不变量

三轴定位（借用框架，非贡献本身）：

| 轴 | 本文坐标 |
|---|---|
| 演化什么 | 仅 Skills/Tools |
| 何时演化 | 主循环反思环节（探索/验证不改资产） |
| 如何演化 | QM 诊断证据 → 反思生成修订并落盘；不改验收标准与 Graph verdict |

### 4.1 验收不变量（全文唯一）

**INV-ACCEPT**：对已归档 DFT/IRC 输出应用人类敲定的交付级 STRICT 条款，判定边/路径是否合格；非模型自评分；非演化产物；系统无权修改条款。  
**单研究单版本**：一篇报告的运行轨迹与发表投影绑定**一个预注册的 STRICT 版本号**；人类若更新条款，视为新研究/新版本网络，不在同一发表投影内混用多版本重判。  
**不包含**：对 Skill/Tool 修订的 retain/rollback；专家对交付包的确认（见 §6.2）。

### 4.2 资产修订纪律（方法不变量，非仅政策口号）

**INV-WRITE**（角色无关）：
1. **仅**确定性验证脚本可写 `evidence` / `endpoint` / `verdict`；任何 LLM 驱动角色（Explore 或 Reflect）均不得手写这些字段，也不得改写验收标准实现；  
2. 每次修订必须写入修订记录（§5.2）并保留版本 diff；  
3. 每次执行必须引用所用资产版本；  
4. 畸形/不可运行修订：不得静默使用——回退到上一可运行版本或跳过该激活点并记失败（设计规定；实现可后续补齐）。

## 5. 主循环：角色 + 算法契约

角色分解的智能体系统：三角色挂在单一主循环上；确定性编排 + 并行 QM worker（计算并行，非自治 agent）。

### 5.1 一轮循环的类型化接口

| 步骤 | 输入 | 输出 | 写权限 |
|---|---|---|---|
| **Explore** | Graph **扩展前沿** \(F\)；资产版本 \(V\)；预算 \(B\) | 边假设集合 \(H\)（含机制假设） | 可写边假设 / 扩展前沿索引 |
| **Validate** | \(H\)；**预注册 QM 协议**；STRICT 版本 | 每次计算尝试的 evidence/endpoint；边级 verdict | 仅确定性脚本写 attempt 与 verdict |
| **Remember** | 本轮 attempt/verdict 与失败签名 | Experience 检索视图；**不新增** Graph 事实字段（边级更新已由 Validate 写入） | 仅 Experience 可追加事件；Graph 侧只做**投影物化**（见下） |
| **Reflect** | Graph 摘要 + Experience；**版本化**失败模式库 | 可选修订 \(\Delta\)；修订记录 \(R\) | 仅 Skills/Tools（可编辑面内）+ Experience 账本 |

**关于 Remember 与 Graph 的写入关系（实现层限定，避免误读）**：事实字段（attempt 的 evidence/endpoint、边级 verdict）全部由 Validate 的确定性写入口产生并落在 attempt 记录与判决档案中。Remember 阶段调用图构建器，但该构建器**不产生新判断**：它把已记录的事实投影成图，并在缓存证据之上叠加**已记录的**重判结果。因此「Remember 不新增 Graph 事实字段」与「图文件在 Remember 阶段被写出」并不矛盾——后者是物化，不是判定。顺序不可颠倒：原始缓存先合并，已记录的重判后叠加（判决高于观察）。

停止条件（设计）：目标路径集合达成 **或** 资源耗尽 **或** 达到预注册的饱和统计（§10）。停止后可进入固定资产评价条件，而非切换到第二套方法。

### 5.2 身份、状态机、扩展前沿、修订记录

**三层对象（避免把科学身份与计算尝试混为一谈）**：

| 对象 | 键 / 内容 | 作用 |
|---|---|---|
| **边假设 (hypothesis)** | 反应物键、产物键、`reaction_kind`、机制标签（可选） | 探索提出的拓扑/机制假设 |
| **计算尝试 (attempt)** | hypothesis_id + 猜测方法/资产版本 + QM 协议版本 + 作业指纹 | 一次具体 QM 计算 |
| **边级判决 (verdict)** | 在指定 STRICT 版本下对 attempt(s) 的汇总状态 | 进入验收投影的依据 |

物种键 = 规范化 SMILES（预注册 canonicalization）+ 电荷/质子化标签。同一 hypothesis 可有多次 attempt；attempt 失败不等于「反应不存在」。

**统一状态词汇（边级 verdict，绑定一个 STRICT 版本）**：

```
hypothesis → has attempts → verdict ∈ {STRICT, evidence_ok, rejected, unresolved}
```

其中 `STRICT` = 通过交付级验收；`evidence_ok` = 有 QM 证据但未达 STRICT（实现层可再标 `validated`/`qm_real`，方法层不区分）；`rejected` / `unresolved` = 未通过或未决。  
**多 attempt → 边级 verdict 汇总规则**：若存在至少一次在当前 STRICT 版本下合格的 attempt，则 hypothesis 的 verdict = `STRICT`（其余 attempt 保留在 provenance，不删除）；否则若存在 evidence_ok 级 attempt → `evidence_ok`；若仅有失败 → `rejected`；若尚无终态 → `unresolved`。  
允许：对同一 hypothesis 在新资产版本下发起新 attempt；**禁止**无 provenance 覆盖旧 attempt/verdict。  
验收投影 = `{hypothesis | verdict = STRICT}`（在报告绑定的 STRICT 版本下）。  
**路径通过**：不仅是 hypothesis 序列上 verdict=STRICT，还必须选定**几何相容的 STRICT attempt 链**（端点几何可衔接、IRC/路径组装一致）；不得把不同 attempt 的端点随意拼成路径。  
当端点键不足以区分机制时，hypothesis 键可附加原子映射/变换签名（预注册规则）。

**扩展前沿 \(F\)**：  
\(F_0\) = 预注册种子物种集（如葡萄糖及声明的溶剂/催化相关物种）；  
\(F_{t} = F_0 \cup \{v \mid \exists e\ni v,\ \mathrm{verdict}(e)\in\{\mathrm{STRICT},\mathrm{evidence\_ok}\} \}\)。  
**扩展前沿 ≠ 验收投影**。

**失败模式库**：人类预定义的**版本化输入资源**（受保护引用，不计入可演化 Skills 产物，也不算记忆贡献）；每次归因必须点名 `(failure_mode_id, taxonomy_version)`。Experience 可归纳摘要，但不得无版本地改写分类法本身。
实现对应 `policy/failure_modes.md` / `.json`（v1，11 个化学模式 + 5 个过程模式）；化学模式由确定性分类器从已记录 attempt 指派，写入时校验，未声明的 id 被拒而非作为自由文本接受；`scripts/qa/test_failure_taxonomy.py` 断言分类器与分类法不发生漂移。过程模式描述机制而非化学结论，归因于它的修订记为 `plumbing`，不支撑能力主张。  
**修订内容来源（防「只是执行手写规则表」）**：Methods 须区分 (a) 专家预置的失败→动作模板库；(b) 反思环节在可编辑面内**生成或选择**的具体修订（参数/模板/组合/规则条文）。主张「自演化」时，C1/C2 证据必须覆盖 (b)，而不能只演示 (a) 的查表执行。

**失败归因（Reflect 最小程序）**：
1. 从本轮/近邻 `rejected`/`unresolved` attempt 读取失败签名；  
2. 映射到当前 `taxonomy_version` 的失败模式；  
3. 在可编辑面内生成或选择修订动作；  
4. 写出修订记录后落盘。

**修订记录 \(R\) 最小字段**（自动落盘 ≠ 系统接纳门）：

| 字段 | 含义 |
|---|---|
| `trigger_evidence` | 触发的边/失败签名 |
| `failure_mode` | 归因模式 |
| `asset_id` / `asset_version_before/after` | 改动对象与版本 |
| `diff` | 可审计 diff |
| `intended_effect` | 预期行为变化（可测） |
| `scope` | 适用 reaction_kind / 子结构 |
| `activation_point` | Explore 打分/选批 / Validate 猜测阶梯 / 其他预定义钩子 |
| `first_downstream_use` | 首次被后续执行引用的时间/边（close 时回填） |
| `expectation_met` | close 时实测（允许 false） |

### 5.3 搜索侧轻量多样性（非主线）

批次选择使用**diversity-aware batch selection**（轻量；非完整 MAP-Elites）：在质量截断子池上，联合 `normalized_quality` 与相对已选/已探索集合的指纹距离（Morgan 等预注册描述子），抑制近重复占用 QM 预算。若实验实际报告 niche/质量–多样性权衡，可标注为 QD-inspired；否则正文只用 diversity-aware 表述。参数与实现细节属 Methods；评价指标属实验章。  
**不把 LLM 思维/指令多样性写入形式化方法。**

## 6. Graph、验收投影与交付包

### 6.1 写入矩阵

- Explore：边假设 / 扩展前沿索引（**不得**写 evidence/endpoint/verdict）；  
- Validate 确定性脚本（含受保护的证据解析器）：attempt 的 evidence/endpoint 与边级 verdict；  
- Reflect：只读 Graph；  
- Remember：只写 Experience，不写 Graph 事实字段。  
无「交付包 → Graph」写入路径。原始 QM 输出归档时应记录内容哈希；解析器属受保护集，不在可演化 Tool 面内。

### 6.2 两类产出与「路径通过」定义

1. **验收网络 / 发表投影**：在报告绑定的 STRICT 版本下 `verdict == STRICT` 的边假设投影。  
2. **专家确认交付包**：通向目标的几何连续路径材料包。

**路径通过（设计定义）**：路径上每条边假设均为 STRICT，且几何/IRC 链连续，并满足打包完整性检查。  
**专家确认**：确认解释与材料完整性，**不是**第二条科学验收门，**不**改写边级 verdict，**不**回写 Graph 事实。

## 7. Experience 与可编辑资产面

Experience：情节事件日志 + 归纳摘要；维护≠演化对象。

### 7.1 可编辑面（收窄后的设计）

| 资产类 | 允许修订 | 不允许 |
|---|---|---|
| **Skills（声明式）** | 可读规则、工作流步骤、失败模式→动作映射、使用条件 | 验收标准条款；伪造 Graph 事实 |
| **Tools（可执行）** | 猜测/扫描**模板与调度参数**、例程组合/顺序、自检阈值（不含理论级别） | 任意无版本代码重写；**改写预注册 QM 协议**（泛函/基组/溶剂化/热化学）；绕过 STRICT；直接写 Graph verdict；改写证据解析器 |

每次修订保留版本谱系与 diff；执行引用 `asset_version`。若实现需要更广的 Tool 代码编辑，必须仍满足 INV-WRITE 与修订记录——但**方法主张的默认可编辑面以上表为准**（优先参数/模板/组合，而非任意代码突变）。

## 9. Skill evolution 验证接口（方法层）

触发链：`执行反馈 → Graph → Experience → 修订 R → 再执行（激活点）→ 复用/对照`

「修订」= 反思落盘 + 版本激活，不是验收标准对 patch 的录取。

### 9.1 C1：修复重放与迁移重放

固定：匹配输入、QM 协议、**同一 STRICT 版本**、同一失败模式 taxonomy 版本；**除被测资产外，其余资产快照保持不变**（若修订有依赖，须在记录中声明依赖闭包并整包对照）。  
变量：目标资产版本（修订前 vs 修订后）。

1. **修复重放 (repair)**：在触发该修订的实例上，新旧资产对照——检验是否修复触发失败。  
2. **迁移重放 (transfer)**：在**独立抽取**、同属该预注册失败类、且非触发集的实例上对照——检验是否可迁移，而非只记住触发例。

终点：目标失败模式是否缓解，或是否达到 STRICT。  
仅修复重放通过而迁移重放失败 → 不得把 C1 写成「能力演化」，应降写为局部修复。

### 9.2 C2：前瞻策略级对照（两侧均冻结）

固定：同一前瞻/held-out 任务集、种子、**QM 预算（主单位：核时；同时报告 attempt 数）**、**同一预注册 QM 协议**、STRICT 版本、初始扩展前沿快照（或预注册的任务暴露协议）。  
变量：**最终演化资产集** vs **初始资产集**（主对照）。定向消融（如去掉某一 Tool 族）仅作**支持性分析**，不替代主对照。  
**两侧在评价窗口内均冻结 Reflect 写权限**——比较的是资产版本，不是「演化阶段 vs 固定阶段」的时间窗混淆。  
终点：预算内成功边比例 / 目标可达性等预注册指标。  
**禁止**：用「演化期轨迹 vs 固定后轨迹」当作 C2 的主对照；**禁止**在资产会改变候选生成时，仍声称「同一候选集合」上的 with/without 为充分因果检验。  
**数据分隔**：用于反复观测饱和的稳定诊断面板 **≠** C2 最终 held-out 测试集，避免停止决策间接拟合评价分布。

### 9.3 案例与时序

Case studies 提供「挑战 → 反馈 → 修订 → 首次下游使用」的可追溯链；时序成立不等于因果获益——因果依赖 §9.1/§9.2。

## 10. 成果展示：固定资产评价条件

定位：**评价条件**，不是第二套方法，不用「阶段1/阶段2」命名。  
作者已选协议（ledger **D-28 / D-29**）：

1. **饱和统计（D-28 / A2）**：诊断面板 = 协同脱水 / 干式质子迁移 / 逆羟醛三类上预注册的少量 attempt；连续 \(K=3\) 窗，成功率或每核时成功边改善 \(<\varepsilon=5\%\) ⇒ 可冻。诊断面板 ≠ C2 held-out。  
2. **固定动作**：冻结 Skills/Tools 版本集合；关闭 Reflect 写权限；Explore/Validate 可继续，但 C2 评价本身在冻结资产上进行。  
3. **前瞻任务集（D-29 / B2）**：1–2 条 held-out 目标路径（或冻资产下对既有交付路径的重发现）；演化期禁止用其结果改资产；C2 比较最终资产 vs 初始资产（§9.2）；主终点 = 几何连续 STRICT 链是否交付（+ 用时/核时）；每臂同一核时帽。  
4. **披露与曲线**：正文零脚本名（D1）；观察性累计 STRICT 边时间曲线作主图 2 辅板（C-aux），不作主对照；图注不得把「演化阶段/固定阶段」画成两套方法。

## 13. Methods 大纲

**M1** 场景与人定边界；环境假设（质子化/溶剂/催化水等）。

**M6** QM 验证与打包。
