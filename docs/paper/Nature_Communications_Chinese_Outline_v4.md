## 文稿定位

**目标期刊：Nature Communications**

本文是一篇以化学发现系统为核心的研究论文。其中心贡献不是宣称某一条糖转化路径在化学文献中首次提出，而是展示一个面向复杂水相反应空间、角色分解的自进化智能体系统：在研究者预先定义目标与验收标准后，系统能够长期运行，自主扩展候选反应、执行量子化学验证、从结果中更新可复用资产，并将可接受的基元步骤组装为通往多个目标产物的统一反应网络。

「自进化」在本文中是一个**范围明确的技术主张**，而不是笼统的营销词：系统只在**能力资产（Skills/Tools，即程序性记忆）**这一个对象上演化；演化发生在主循环的**反思环节**，由结构化的量子化学执行反馈提供归因证据，修改提议由反思环节的自然语言归因生成。验收标准是**人类敲定的、版本明确的交付级规则**（`strict-pathway-validation`），只判定一条反应边/路径是否符合该化学验收规范，**不产生「资产改动被系统接纳」这类信号**——不存在 patch 级的 retain/rollback，资产修改的价值由后续复用范围与受控 with/without 对照来检验，不是由验收标准本身背书。三者共同构成一个可被证伪、可逐项核验的技术范围（借用近期自进化智能体分析框架定位自身，而非宣称与某个已定型的标准分类严格对齐；见 §1.4、§2.1）。

通向三个目标产物（HMF、HAA、糠醛）的经专家复核端到端路径是系统能力展示与机制洞见的载体；其中 HAA 现有两条独立的路线（短逆羟醛 R1，与沿糠醛主干再裂的 R2）。多路线是网络结构事实，不写成化学新颖性主张。它们证明系统不止能输出孤立候选，还能交付可检查的路径和网络。

## 一句话主张

在人定目标与交付级验收边界下，结构化 QM 失败被转化为可追溯的 Skills/Tools 修订，从而改变后续探索/验证行为；网络与交付路径是单一主循环（Explore→Validate→Remember→Reflect）的副产物。当演化收益趋于饱和后，固定资产并关闭反思，在前瞻任务上以**最终资产 vs 初始资产**（两侧均冻结）检验自主发现能力。

## 两条可证伪的方法主张（写作时须可对上实验）

| 主张 | 主终点 | 主对照 | 失败条件 |
|---|---|---|---|
| **C1** 结构化 QM 反馈 → 可追溯程序性修订 → 改变后续行为 | 目标失败模式下降或同预算成功边比例上升 | **修复重放 + 迁移重放**（同输入/同 QM 协议/同 STRICT；其余资产快照固定） | 行为无变化 / 无法指认激活 / 仅触发例改善无迁移 |
| **C2** 累积资产在固定 STRICT 下改善前瞻发现 | 同一前瞻任务集上的交付/成功率 | **最终演化资产集 vs 初始资产集**；**两侧评价均冻结 Reflect** | 前瞻无增益 / 演化期任务泄漏进前瞻集 |

观察性累计曲线、演化期 vs 固定后时间窗轨迹**不是** C2 主对照（见 §4、Method Framework §9–10）。

## 核心贡献

1. **QM 反馈驱动、边界收紧的程序性资产演化闭环（对应 C1）**  
   单一主循环串起探索、验证、记忆与反思修订；演化对象仅 Skills/Tools；人类敲定的 STRICT 只锚定边/路径质量；每次修订是带证据与版本谱系的自动落盘干预（非 patch 接纳门）。资产价值由复用、修复/迁移重放与受控对照检验，不由验收标准背书。

2. **可审计的化学实例化：状态—修订—交付证据链（对应 C2 产出面）**  
   Graph/Experience 分置科学状态与经验；写入矩阵明确；验收投影与专家确认交付包均为产出且不回灌 Graph。统一网络（葡萄糖→HMF/HAA/糠醛；HAA 两条路线）与专家确认交付包是能力展示载体，不是独立「化学首创」贡献。

3. **可迁移的机制—方法知识（案例层）**  
   协同脱水、干式互变异构、β-羰基活化逆羟醛三类案例展示「挑战→反馈→修订→复用」链；正文以更新后复用范围克制陈述；§3.4 的 with/without 为支持性评估，**不替代** C1 的修复/迁移重放。

4. **可审查的交付形式**  
   几何链、TS、频率、IRC、能量清单与专家确认交付包；可从路径图回溯逐步计算证据。

# 摘要（中文草案）

复杂反应网络的量子化学发现受到化学空间组合爆炸、过渡态搜索不稳定及验证结果难以累积利用的共同限制。我们提出一个面向复杂反应网络量子化学发现的角色分解智能体系统：系统以一套持续运行的主循环——探索候选、执行量子化学验证、将结果写入科学状态与经验记忆、修订可复用的 Skills/Tools——把验证结果转化为持续增长的发现能力。演化范围被明确限定：只演化 Skills/Tools（程序性记忆），由结构化的量子化学执行反馈提供归因证据，反思环节据此生成修改提议。研究者预先定义目标产物、验收标准与资源预算（人定边界，系统无权演化）；验收标准是人类专家敲定的、版本明确的计算规则，只判定反应边/路径是否合规，不构成对资产改动的接纳信号。科学状态由 Graph Memory 持有并组织为目标导向的统一反应网络；经验教训与资产变更效用记入 Experience Memory。以水相葡萄糖转化为高复杂度测试场景，系统自主构建并交付了通向 5-羟甲基糠醛、羟基乙醛和糠醛的经专家复核路径（羟基乙醛含两条独立路线）。运行轨迹表明，系统可将协同脱水、干式互变异构和 β-羰基活化逆羟醛等挑战转化为可复用的 Skills 与 Tools；正文报告更新后的复用范围，并以受控 with/without-skill 评估检验是否降低同类型验证成本。当能力资产的持续修订对指标的边际贡献趋于饱和后，我们固定资产、关闭反思环节，并在前瞻任务上以最终演化资产对照初始资产（两侧均冻结）检验自主发现能力，作为自演化价值的成果展示。该工作展示了在人定边界下，一个持续运行的智能体主循环如何将量子化学计算从孤立验证任务转变为可积累、可审查的反应网络发现过程。

# 正文大纲

## 1. 引言：从孤立 TS 搜索到可积累的反应网络发现

### 1.1 复杂水相糖转化中的发现难题

- 葡萄糖通向 HMF、HAA 和糠醛涉及异构化、脱水、环化、质子迁移与 C–C 断裂等多类基元事件。
- 难点并不只是「找到一个 TS」，而是让大量候选在同一网络中具有明确来源、可验证终点和可继续扩展的几何/结构状态。
- 传统工作流常将路径规划、TS 猜测、IRC 判读、证据整理视为相互分离的人工任务，失败经验难以跨任务累积。

### 1.2 当前自动化反应探索的缺口

- 大规模候选生成容易产生拓扑上可行、但在量子化学验证中无法连接目标物种的边。
- 通用 TS 搜索对柔性糖类、协同质子转移和 C–C 断裂缺乏反应类型适配。
- 即使产生了有效计算结果，候选、失败端点和方法经验也常无法持续改变后续搜索行为——这正是近期自进化智能体文献所称的「经验未被转化为能力更新」的缺口，而不是单纯的算力或搜索算法问题。

### 1.3 本文的回答

- 提出一个角色分解的智能体系统：Explore→Validate→Remember→Reflect 四步挂在同一主循环上（见 §2.1、M2），不是「LLM 提议 + QM 执行」流水线，也不是多自治 agent。
- 以**人定边界**框定目标与验收；以 **Graph / Experience** 分置科学状态与经验；以 Skills/Tools 为唯一演化对象；用 **C1（修复+迁移重放）** 与 **C2（最终资产 vs 初始资产，两侧冻结）** 使自进化主张可证伪。
- 以专家确认交付路径、统一网络和三类机制—方法案例展示能力；饱和后固定资产/关反思作成果展示（§4），不用「阶段1/阶段2」对仗命名。

**引言结尾主张：** 本工作关注的是「系统如何在人定边界下学习并构建可审查的化学网络」，而非把单条路线包装为化学首次发现。

### 1.4 概念定位：借用「演化什么/何时/如何」分析框架给本文的「自进化」定位

近期综述提出一个仍在形成中的分析框架，把智能体自进化拆成三个问题——**演化什么**（模型参数/记忆/工具/工作流脚手架）、**何时演化**（任务执行期内的实时适应，还是任务执行之间的跨批次改进）、**如何演化**（梯度更新、强化学习、群体演化，或结构化反馈驱动）。本节借用该框架给本文系统定位，而不是宣称这是已经定型、唯一正确的标准划分。

| 轴 | 本文坐标 | 与常见混淆点的区别 |
|---|---|---|
| 演化什么 | 仅**能力资产**层（Skills/Tools，程序性记忆）；模型参数不参与训练、不演化 | 不是「记忆内容自动生长」——Graph/Experience Memory 的写入由确定性脚本或反思环节的记录动作完成，记忆本身不是被演化的对象（见 §2.2 写入矩阵） |
| 何时演化 | 主循环的**反思环节**：探索与验证阶段不修订资产，只把结果写入科学状态与经验记忆；资产修改只在反思环节由 LLM 归因后提出并落盘 | 不是「执行阶段处于某种测试时演化模式」——探索与验证阶段不演化，只是任务执行 |
| 如何演化 | 结构化 QM 执行反馈（端点身份、失败模式、no_match 比例等诊断信息，不只是单一 verdict）提供演化证据；演化的**修改提议**由反思环节的自然语言归因与规则生成产生（非梯度更新、非强化学习、非群体演化）；提议的**落盘范围**受运行策略约束限定：不改写验收标准实现，不手改 `graph/reaction_network.json` | 不应把「诊断证据」窄化为单一 STRICT verdict——反思环节实际读取的诊断信息更丰富；也不应倒过来把验收判决当成「资产修改被接纳」的信号，见下 |

**关于验收标准的性质与边界**：验收标准（`strict-pathway-validation`）是**人类敲定的验收标准**——由专家设定条款、经 LLM 整理成可执行规则，最终版本以专家确认为准。它只判定一条反应边/路径是否符合该化学验收规范，**不产生「某次 Skill/Tool 改动被系统接纳」这类信号**——不存在 patch 级的 retain/rollback 机制。系统无权自主演化该标准；标准的产生与更新来自人类专家，不来自反思环节。

必须同时交代一处会削弱「独立」措辞的实现事实：承载验收标准的 skill 与可演化方法知识目前同文件，且该 skill 以 `layer: skill` 身份出现在 `timeline.jsonl` 的 asset_event 中。因此「验收标准实现划在可演化 Skills/Tools 集合之外」目前只是运行协议主张，不是文件/权限隔离事实；后续工程应拆分为 protected acceptance policy、executable validator、evolvable method Skill。

适用边界：验收标准保证的是对该标准版本下计算协议的一致应用，不是化学绝对真值。上述设计与近期 verifier-grounded evolution 的经验观察（术语锚点 B：Microsoft Research *Agentic Evolution* 综述，2026；仅作设计动机、不作可靠性证明）部分一致，不构成独立证明。

**关于变更纪律与治理**：反思环节对 Skill/Tool 的修改是自动提出、自动落盘的，不经过逐次人工点击批准；可信度来自运行策略约束（不改写验收标准或科学状态文件；按规定 open/close 留痕），而非技术强制。账本体量须如实披露（见 Methods M4）：截至草案日正式账本条目很少，多数历史资产变更的时序仍依赖运行文件与 timeline 重建，**不是**已对全部历史资产修订提供可审计因果链条的累积账本。

## 2. 角色分解的自进化智能体系统架构

### 2.1 主循环与角色分工

系统由一套持续运行的**主循环**与按职责挂接的角色组成；角色挂在循环上，不是多个始终并发、具有独立策略权重和通信边界的自治模型。核心实现（`tools/reaction_network/`）里，Explore/Validate 由确定性脚本与并行 QM worker 完成（图构建、模板扩展、验证），经 JSON/分片缓存交接，不共享 Python 内存；Reflect 由同一会话在迭代间隙读取上述文件、决定是否修订资产。据此统一使用**角色分解的智能体系统**（role-decomposed agentic system）；「多智能体」仅作对比用语。

主循环四步（与 Method Framework §5 对齐；QM worker 并行 ≠ 自治 agent）：

| 步骤 | 职责 | 写权限 |
|---|---|---|
| **Explore** | 从**扩展前沿** \(F\) 做模板扩展与 diversity-aware 选批（§2.5），提出边假设集合 \(H\) | 可写边假设 / 扩展前沿索引；**不得**写 evidence/endpoint/verdict |
| **Validate** | 在预注册 QM 协议下对 \(H\) 做猜测阶梯与 DFT/IRC；确定性脚本写 attempt 的 evidence/endpoint 与边级 verdict | **仅**确定性脚本（含受保护证据解析器） |
| **Remember** | 整理本轮 attempt/verdict 与失败签名进入 Experience 检索视图 | 只追加 Experience；**不新增** Graph 事实字段（边级更新已由 Validate 写入） |
| **Reflect** | 失败归因 → 可选修订 Skills/Tools；写修订记录（open/close） | 仅可编辑面内的 Skills/Tools + Experience 账本；只读 Graph |

**INV-WRITE（角色无关）**：任何 LLM 驱动角色均不得手写 evidence/endpoint/verdict，也不得改写验收标准实现或预注册 QM 协议。

网络扩张是该循环持续交付路径的**副产物**，不是独立「扩网」流程；论文删除 `auto_loop`（ledger D-16）。

### 2.2 科学状态：Graph Memory、扩展前沿与验收投影

- **Graph Memory** 是持久化科学状态与来源账本。方法层统一三层对象，避免把「反应是否存在」与「某次计算是否过门」混谈：
  - **边假设 (hypothesis)**：反应物/产物键、`reaction_kind`、机制标签；
  - **计算尝试 (attempt)**：某次 QM 计算（含资产版本与作业指纹）；
  - **边级判决 (verdict)**：在**报告绑定的单一 STRICT 版本**下对 attempt(s) 的汇总。
- **统一状态词汇**（边级）：`verdict ∈ {STRICT, evidence_ok, rejected, unresolved}`。`STRICT` = 通过交付级验收；`evidence_ok` = 有 QM 证据但未达 STRICT（实现层可再标 `validated`/`qm_real`，方法层不区分）；attempt 失败 ≠「反应不存在」。多 attempt 汇总：任一合格 attempt → 边级 `STRICT`（其余 attempt 留 provenance）。
- **写入矩阵**：Explore 写边假设/扩展前沿索引；Validate 确定性脚本写 evidence/endpoint/verdict；Reflect 只读 Graph；Remember 只写 Experience。无「交付包 → Graph」回写。原始 QM 输出可记内容哈希；证据解析器属受保护集（工程纪律，非开放「防骗 STRICT」议题；见 R-14）。
- **扩展前沿 \(F\)**（用于继续探索）：\(F_0\) = 预注册种子物种；\(F_t = F_0 \cup \{v \mid \exists e\ni v,\ \mathrm{verdict}(e)\in\{\mathrm{STRICT},\mathrm{evidence\_ok}\}\}\)。**扩展前沿 ≠ 验收投影**。
- **验收网络 / 发表投影**：`{hypothesis | verdict = STRICT}`（绑定一个预注册 STRICT 版本）。**路径通过**：每条边假设均为 STRICT，且选定**几何相容的 STRICT attempt 链**（端点可衔接、IRC/路径组装一致）+ 打包完整性；专家确认交付包确认材料完整性，**不是**第二条科学验收门，不改写 verdict、不回写 Graph。

### 2.3 经验与能力：Experience Memory → Skills/Tools（程序性记忆）

- **Experience Memory** 单独保存失败教训与 Skills/Tools 变更记录（含效用反馈），服务反思环节；允许对已记录事件做**受控的记忆维护**——教训合并、低效用条目降权——但这是记忆维护操作，不是本文限定的「演化对象」（本文只限定 Skills/Tools 演化；Experience Memory 本身不演化），也不得覆盖人定验收标准或目标集合。功能上，它更准确地描述为**以情节事件日志为底座、辅以归纳性 lesson 摘要视图的经验存储**：每条原始 open/close 事件都绑定具体的观察时刻（`opened_at`/`closed_at`）、具体的失败签名和具体的效用测量，具有典型情节记忆属性；合并后的通用教训摘要则带有一定的归纳/规则化性质，正文与 Methods（M4）明确承认这一混合性质，不笼统称其为「纯情节记忆」。
- 变更纪律：改 Skill/Tool 前 `open` 一条账本（观察、变更、可测预期），若干轮后 `close`；**未达预期也如实 close**，否则只能被证实的记录不是证据。这一账本是**按规定审计流程留痕的记录**，不是逐次人工批准门——修改由反思环节自动提出并自动落盘，可信度来自运行策略约束（不碰验收标准/图文件）与账本的事后可审计性，而不是人工签核环节；账本体量与覆盖范围须如实披露（见 Methods M4）。
- Skills/Tools 是被修订的**能力资产**，从 CoALA 对「显式程序性记忆」的功能视角看，二者共同构成**程序性记忆**（procedural memory：不是「记住了什么事实」，而是「知道该怎么做」）的两种互补形态——但 Skill/Tool 二分本身是本文的**项目自定义工程划分**，不是 skill-library 一脉文献（Voyager、SAGE 等）的标准命名。本文额外做出这一划分的理由是可变性风险不同，而非声称对齐某个既有标准：
  - **Skills** 沉淀可读规则与工作流；本文有意保持其自然语言/规则形式，而不做 Voyager 式的按嵌入检索的代码片段库，因为 Skill 修改的是「反思环节如何解释失败、何时换方法」的决策规则，需要人可读、可审计。
  - **Tools** 实现猜测、扫描、筛选、调度与自检——是直接触达确定性 QM 流水线的可执行例程，属于更严格版本管理的对象。
  - 二者的**可变性风险**不同——改一条 Skill 的最坏后果是一次反思误判；改一个 Tool 若引入 bug，会直接污染下游 QM 结果，这是本文拆分二者的主要依据（详见术语锚点 D）。
  - 它们由反思环节修订、由探索/验证角色消费，不与 Graph Memory 并列成「第 N 层记忆」。

四类对象（取代旧「层表」）：

| 类别 | 记忆功能对应 | 成员 | 谁写入 | 可展示证据 |
|---|---|---|---|---|
| 科学状态记忆 | 经验证事实子图承担语义/世界状态记忆功能；同时含候选/未决/失败上下文 | Graph Memory | Explore（假设/前沿）与 Validate 确定性脚本（evidence/endpoint/verdict）；Reflect 只读 | 网络版本、边状态、扩展前沿、验收投影 |
| 经验记忆 | 情节事件日志为底座 + 归纳性 lesson 摘要视图 | Experience Memory | 反思环节 | lessons/updates 账本、方法级 edit hint、utility（含 false） |
| 能力资产 | 程序性记忆（规则态 + 可执行态，项目自定义子类） | Skills, Tools | 反思环节修订，自动落盘 + open/close 规定留痕 | 可读 Skill、源码、后续复用记录 |
| 产出/证据 | （非记忆，投影/证据对象） | 验收网络、交付路径；verdicts / `.out`·`.hess` / deposits | 由 Graph 投影或旁路存证 | 专家包、自检脚本、判决档案 |

### 2.4 人定边界与验收标准

- 目标产物集合、验收标准与计算预算由研究者定义，**系统无权自主演化标准**。验收标准是人类专家敲定的、版本明确的规则集合（`strict-pathway-validation` skill），只判定一条反应边/路径是否符合该化学验收规范；**不是演化产物，也不产生「资产改动被接纳」的信号**。
- 反应类型、迁移氢、断键/成键坐标、软模和 IRC 端点均进入工具与规则层。
- 「化学领域适配」的关键是：系统将 QM 输出中的结构化信息变为可执行的下一步约束，而非只生成化学文字解释。

### 2.5 轻量多样性设计（非主线）

搜索侧使用 **diversity-aware batch selection**（轻量；非完整 MAP-Elites）：在质量截断子池上，联合质量分与相对已选/已探索集合的指纹距离，抑制近重复占用 QM 预算。若实验实际报告 niche/质量–多样性权衡，可标注 QD-inspired；否则正文只用 diversity-aware。参数与实现细节属 Methods M5。

**不把 LLM 思维/指令多样性写入形式化方法。** 叙事上若需一句拔高为 machine-creativity-inspired，位置与克制程度见开放项 T-08；不展开实现，亦不构成核心贡献。

与「新颖性盲态三分类协议」（化学文献意义上的新颖性）严格区分：此处距离量是搜索机制，后者是认知诚实协议。

## 3. 自演化证据：从执行反馈到可复用 Skills

本节是全文 **skill evolution** 证据的核心。须先说明：以下三个案例均为可执行态资产（Tools）；规则态 Skill 的演化证据不在正文展开为独立 case study，以免与验收标准独立性叙事冲突。用语与分类对齐 Ding et al.（arXiv:2606.11435）关于执行反馈驱动 skill 演化的定义：本工作以量子化学验证得到的**执行反馈**（execution feedback，结构化 QM 证据，含端点身份、失败模式等诊断信息，非单一 verdict）为证据，由反思环节生成 Skills/Tools 的修改提议并自动落盘（受运行策略约束限定；修改提议按规定的 open/close 流程留痕，历史资产的形成时序通过运行文件和 timeline 重建）——即程序性记忆在主循环反思环节的演化，证据来自执行反馈、修改提议由反思环节推理产生——并维护可复用的 skill 库与结构化失败记录；评估采用 with/without-skill 对照以衡量 skill utility。

触发链（口径）：

`执行反馈 → 入 Graph Memory（事实）→ 入/检索 Experience Memory（教训）→ 修订 Skill/Tool → 再执行 → 复用范围`

证据分三类（此处「类」指证明材料，不是资产结构）：

1. **Skill-evolution case studies**（§3.1–3.3）：若干真实样例——挑战 → 执行反馈入图 → Skill/Tool 修订 → 更新后复用范围 → 机制洞见。计数纪律见 §3.0。
2. **路径构建轨迹**（§5.2）：各能力展示路径的失败 → skill/tool 更新 → 后续步骤复用 → 验收通过。用于说明路径是 skill evolution 过程中的产物；最小检验是路径上存在「先更新、后复用」，而非仅有反复试错。
3. **C1/C2 与支持性 with/without**（§3.4–§4）：预注册后的受控对比；with/without 不替代修复/迁移重放与最终-vs-初始资产对照。

执行反馈中的失败与否决（旁观水被拒、自动探索低产、旧判据步骤等）写在相应 case study 与 Methods 里，作为演化过程的一部分。资产变更按规定流程入 Experience Memory 账本以备审计（历史覆盖范围见 Methods M4）；正文只展开下列三个案例。

### 3.0 更新后复用范围（陈述纪律）

一个 Skill/Tool 更新之后，只有在它出现**之后**才被验收的边可计入其复用范围；更早的边无论叙事如何都不在范围内。资产出现日期取自运行记录中该资产名首次出现的时刻（估计量），验收边日期取自判决记录时间戳（验收事件本身）；定义见 `CONTEXT.md`，日期来源见 `docs/adr/0002`。数据在 `evidence/timeline.jsonl`。

**统一验收标准后的重算要求**：本文改为单一验收标准后，网络验收边计数与复用范围须按该标准重算，不沿用 v3 草案中双层口径下的数字；投稿前重跑 `repin_state.py`/`build_timeline.py` 统一基线后再锁定正文数字（见文末「待钉死的开放项」）。

记录限制须交代：部分验收边缺少 `reaction_kind` 标注，故按反应类型计的复用范围会窄于按时间计的范围；这是记录缺失，不是化学难度结论，具体比例待重算后披露。

§3.1–3.3 各 case study 统一结构：**挑战 → 执行反馈（入 Graph Memory）→ Skill/Tool 修订 → 更新后复用范围 → 机制洞见**。

### 3.1 协同脱水：从单坐标断键到 C–O / β-H 共驱扫描

- **挑战**：糖类脱水的单一断键坐标无法稳定表达协同离去和质子迁移，容易给出非反应性或错误分支。
- **资产演化**：形成协同脱水规则，并实现 C–O 断裂与 β-H/质子迁移共驱的约束扫描工具（`constrained_scan_guess.py`）。
- **更新后复用范围**：其后验收边数量待按统一验收标准重算后披露（见 §3.0）；按反应类型标注计的复用范围因标注缺失显著更窄，具体比例待重算。
- **洞见**：对该类体系，正确的反应坐标是协同事件而非孤立键长；这是一条可迁移的搜索设计原则。

### 3.2 干式互变异构：从两性离子端点到原子映射的非对称质子迁移

- **挑战**：表面上具有强虚频的候选仍可能沿 IRC 落入带电/两性离子端点，不能直接进入中性路径链。
- **资产演化**：Graph Memory 保存端点错配模式；系统形成基于原子映射的供体—受体—迁移氢识别，并实现非对称干式质子迁移扫描（`dry_proton_guess.py`），它取代的是早先的水中继猜测（`water_relay_guess.py`），后者因旁观水无法通过验收标准中对该类机理的要求而被否决。
- **更新后复用范围**：该工具晚于多条已交付路线的关键计算窗口，因此对这些路线的贡献为零；其后验收的边数量少，具体数字待按统一标准重算后披露（见 §3.0）。交付包中对应的互变异构步骤由前置的手工指定索引扫描（`proton_scan.py`）产出，不能记在本工具账上。
- **读法**：这是一条完整的执行反馈驱动演化链（失败模式 → 方法替换 → 工具化），价值在链条可核，不在下游产量；勿写成「后续被广泛复用」。
- **洞见**：TS 搜索成功不能由单一虚频代替；反应端点身份决定该鞍点是否真正属于目标网络。

### 3.3 β-羰基活化逆羟醛：从直接断裂候选到 C6→C5 网络连接

- **挑战**：直接 C–C 断裂的直觉候选可能回到起始构型或产生无法纳入网络的分支。
- **资产演化**：系统将失败模式记录为对反应中心电子结构的约束，形成 β-羰基活化与耦合质子迁移的逆羟醛选择规则，并开发针对性的松弛扫描/TS 搜索流程（`retroaldol_ts.py`）。
- **更新后复用范围**：其后验收边数量待按统一标准重算后披露（见 §3.0）；该资产对应的关键边即 C6→C5 的网络连接，本案例的贡献应以这一条连接的结构意义论证，而不以数量论证。
- **洞见**：C–C 断裂是否可作为可验证基元事件，取决于局部羰基活化和协同质子重排；该结论是系统从候选筛除和验证中获得的机制先验。

### 3.4 因果检验接口与 with/without（预注册）

**主因果接口（对齐 Method Framework §9）**：
- **C1**：对代表性修订做**修复重放**（触发例）+ **迁移重放**（同失败类、非触发集）；固定匹配输入、QM 协议、STRICT 版本与其余资产快照。
- **C2**：见 §4——在前瞻任务集上比较**最终资产 vs 初始资产**（两侧冻结）；禁止把「演化期轨迹 vs 固定后轨迹」当作 C2 主对照。

**支持性 with/without（不替代 C1/C2）**——协议见 `HANDOVER.md` 第十一节：
- **Benchmark A（with vs without skill）**：同反应类型内，现行 Skill/Tool 可用与否对到达 STRICT 的猜测次数/成功率（skill utility；Ding et al.）。
- **Benchmark B（with vs without structured failure records）**：可读失败端点/模式与否对重试成本的影响。
- 资产会改变候选生成时，不得声称「同一候选集合」上的 with/without 为充分因果检验。
- 跑前复制到 `evidence/benchmarks/PREREGISTER.md`；结果**不**并入主图 2（主图 2 服务 §4/C2）。
- 若某条无差：收缩该条主张，保留 §3.1–3.3 case studies。

**正负对照（判据分辨力，非 skill utility）**：表见 `evidence/controls.md`。
正对照＝交付包已收敛 TS 几何经现行验收标准自检（各交付包自检 PASS）；
负对照 A＝强制水中继猜测在现行验收标准下不得通过（含相关案例的 `force_water` 结果）；
负对照 B＝仅从 SMILES 重猜的复现战役（通过率与算力设置待披露）。这些衡量的是**判据能否拒收应失败的方法**与猜测难度，**不是**能力增益；旁观水故事改写为负对照，不再当逸事。

## 4. 成果展示：固定资产评价条件（对应 C2）

本章是自演化闭环的**评价条件 / 价值验证**，不是第二条方法主线，不用「阶段1/阶段2」命名（D-18/D-19）。

### 4.1 饱和统计与固定动作（ledger **D-28** = 方案 A2）

- **诊断面板**：三类机制反应——协同脱水、干式质子迁移、逆羟醛——上预注册的少量 attempt（列表预注册时锁定）。
- **规则**：连续 **K=3** 个评估窗，成功率或每核时成功边相对窗口改善 **< ε=5%** ⇒ 可固定资产。
- 诊断面板 **≠** C2 held-out 前瞻任务集。
- **固定动作**：冻结 Skills/Tools 版本集合；关闭 Reflect 写权限；Explore/Validate 可继续，但 C2 评价本身在冻结资产上进行。

### 4.2 C2 主对照：最终资产 vs 初始资产（ledger **D-29** = 方案 B2）

- **任务集**：1–2 条 held-out 目标路径（或既有交付路径在冻资产条件下的「重发现」）；路径 ID 预注册时填写。
- **对照臂**：最终演化资产集 vs 初始资产集（演化开始前快照）；两侧评价窗口内均冻结 Reflect；同一预注册 QM 协议与 STRICT 版本。
- **预算 / 主终点**：每臂同一核时帽（兼报 attempt 数；核时帽预注册时填写）；主终点 = 是否交付**几何连续 STRICT 链**（是/否 + 用时/核时）。
- **披露（D1）**：正文零脚本/实现文件名，只用功能名；Methods 可保留必要路径引用但不把脚本名当方法主角。
- **禁止**：用「演化期轨迹 vs 固定后轨迹」当作 C2 主对照。

### 5.2 能力展示路径（三个目标、若干条交付级路线）

各路径同时是系统能力展示，也是 **skill evolution**（执行反馈 → 更新 skill/tool → 复用）过程中的产物。除最终链外，引用构建轨迹（字段见 `HANDOVER.md` 第十节）：失败尝试 → Skill/Tool 更新 → 后续步骤复用该资产 → 验收通过。
若某路径只有反复失败后偶然通过，中间没有可指认的资产更新与复用，则正文仅作能力展示，不强称 skill evolution。
HAA 的两条路线是网络结构事实（同一目标、不同骨架路径），**不**据此主张化学首创。

#### 5.2.1 葡萄糖→HMF

- 展示从开放链糖中间体、连续脱水与环化到 HMF 的端到端链。
- Case study 衔接：协同脱水工具（`constrained_scan_guess`）的更新及其在后续脱水步中的复用。
- 指向专家确认交付包 `glucose_hmf_review_v3` 和逐步 QM 证据。

#### 5.2.2 葡萄糖→HAA（两条路线）

- **HAA_R1**（`glucose_haa_review_v1`）：较短分支逆羟醛路线。
- **HAA_R2**（`glucose_haa_review_v2`）：与糠醛主干共享前若干步至 D-木酮糖，再裂解为 HAA + DHA-enol。这些步骤是糠醛交付包的复用计算，不是第二次独立发现。
- 两条路线统一按**专家确认交付包**口径披露完成状态（不使用「待复核/已确认」双重命名）；具体逐步验收记录置于 Methods 与补充材料。

#### 5.2.3 葡萄糖→糠醛

- 展示 C6→C5 网络连接后进入戊糖/呋喃路线的完整链。
- 构建轨迹重点：两性离子失败后的机制改道、旁观水被否后的方法转向、逆羟醛连接的更新与复用。
- 不宣称该化学路径本身首次见于文献；用网络图展示该连接对统一网络的结构意义，以及与 HAA_R2 的主干共享。

### 5.3 路径作为系统能力的证据

- 若干交付级包共同证明系统可以跨多个反应类型和中间体层级，完成「候选生成—TS 验证—端点判读—几何链式组装—专家确认交付」的全流程，并在同一目标上给出多于一条可审查路线。
- 论文不将这些路径等同于全部水相糖化学；它们界定了一个可审查、目标导向的网络子空间。

## 6. 讨论：可演化化学资产如何改变计算发现工作流

### 6.1 从一次性计算到持续积累的发现过程

- Graph Memory 使成功、失败和未决候选都成为下一轮搜索的输入（其 evidence/verdict 字段只由确定性脚本写入，反思环节只读不写）——这也是本文对「何时/如何演化」给出的具体答案：科学状态记忆本身不演化，只有建立在其上的程序性记忆（Skills/Tools）在主循环的反思环节演化。
- Experience Memory 以情节事件日志为底座记录教训与资产变更，可检索、可计量（含未达预期），为程序性记忆修订提供可审计机制（观察 → 变更 → 预期 → 实测）；其归纳性 lesson 摘要允许受控维护，但这属于记忆维护，不计入「演化对象」。账本体量的如实披露见 Methods M4。
- Skills 将化学经验显式化并保持可读；Tools 将经验转化为稳定、可执行的计算操作——二者由反思环节修订、由探索/验证角色消费。
- 两类记忆各司其职、能力资产可复用，避免系统每次从零开始处理类似的机制困难。
- 把这三类功能对象（科学状态记忆、经验记忆、能力资产）放回 §1.4 的坐标系重述：本文提供的不是一个通用的「会自己变强的智能体」，而是一个在**演化对象**（仅程序性记忆）、**演化时机**（仅主循环的反思环节）、**演化信号**（结构化 QM 执行反馈提供诊断证据，修改提议由反思环节推理生成）三个维度都收紧到最小必要范围的具体实例——这种收紧本身，是让「自进化」在高成本、高风险的科学验证场景下仍然可信、可审计的前提，而不是功能上的让步。

### 6.2 发现系统的可解释性与可审查性

- 每条发表级路径都可回溯到逐步计算证据；每个机制—方法案例都可回溯到触发它的失败模式与后续复用。
- 与仅产生候选列表的系统相比，本文系统的产物是具有证据状态、机制解释与可审查交付物的网络。

### 6.3 适用范围与后续方向

- 本文的化学结论限定于水相/水热糖转化的目标导向网络，不将其推广为穷尽性网络或干态热解结论。
- 后续可将该闭环迁移到其他反应体系，并用预注册任务集开展更严格的模块消融和跨体系评估。
- 网络数据可为更快的势能面近似、反应图学习和实验优先级选择提供高质量起点。

# Methods 大纲

## M1. 研究场景、目标与人类定义的边界

- 水相/水热糖转化的计算范围与目标产物。
- 研究者预先定义的目标、验收标准和资源预算（人定边界，系统无权演化）。
- 系统在长时段运行内不逐步指定反应步骤的工作方式。

## M2. 功能角色型智能体架构与主循环

- 主循环四步：Explore→Validate→Remember→Reflect；Explore/Validate 不修订资产；Reflect 只读 Graph、修订可编辑面内 Skills/Tools（§2.1/§2.2；INV-WRITE）。
- 实现：Explore/Validate 由确定性脚本与并行 QM worker 完成；Reflect 由同一会话在迭代间隙决策。并行 worker = 计算并行，非自治 agent。
- 正文统一使用**角色分解的智能体系统**；论文不出现 `auto_loop`/routing 方法主张。
- 长时段续跑、资源限制与可恢复执行；预注册 QM 协议（泛函/基组/溶剂化等）不在可演化 Tool 面内。

## M3. Graph Memory、验收投影与审计钉

- 三层对象：hypothesis / attempt / verdict；边级词汇 `{STRICT, evidence_ok, rejected, unresolved}`（实现层 `validated`/`qm_real` ⊂ evidence_ok）。
- **扩展前沿** F：STRICT ∪ evidence_ok 端点可达（+ 种子 F0）；**验收投影**仅 STRICT；路径 = 几何相容 STRICT attempt 链。
- 网络去重、前沿选择、diversity-aware 选批参数。
- **审计钉与升钉**：`graph/audited_strict_edges.json`；`scripts/reflect/repin_state.py`；smoke 校验不写死条数。
- **验收标准**：人类敲定、单研究单 STRICT 版本；系统无权修改；更新条款 = 新研究/新版本网络，不混用重判。
- **单一验收标准下网络计数须整体重算**；重算前数字不写入正文。

## M4. Experience Memory、Skills 与 Tools（程序性记忆的两种形态）

- Experience Memory：`evidence/experience/lessons.jsonl` 与 `updates.jsonl`；open/close 与 utility（含未达预期）——原始事件对应情节记忆的标准要素（时间戳、观察上下文、后果测量），合并后的 lesson 摘要视图带归纳/规则化性质，二者在本节明确区分，不笼统合称「情节记忆」。
- Skills/Tools 形成的触发事件、来源、适用范围及后续调用记录；Skills 与 Tools 的区分标准（可读规则 vs 可执行例程，项目自定义划分，见正文 §2.3）及各自的变更落盘方式（自动提出、自动落盘、按规定的 open/close 审计流程留痕，不设逐次人工批准环节；该流程目前是运行策略层约定，非技术强制）。
- 三个机制—方法案例的因果链重建方法。
- **账本体量披露**：正式账本条目数量、覆盖的历史资产案例比例，须在投稿前如实统计并披露，不据此声称已对全部历史资产修订提供可审计因果链条。主图 5 若展示账本样例须同时标注总条数。

## M5. 候选生成与轻量多样性机制

- 反应模板前沿扩展。
- 轻量多样性设计的具体实现（候选打分的 fingerprint novelty 加权、批次选择的 quality-diversity-aware 贪心选择、路线登记的 niche/divergence gate）置于本节与扩展数据；正文 §2.5 只做原理性说明，不展开参数与代码路径。
- 用词纪律：本节使用「候选与已探索空间/已注册路线的结构差异度」指代上述距离量（不使用「结构新颖度」，避免与新颖性盲态协议的「化学新颖性」用词冲突）。
- LLM 探索侧的思维/指令多样性设计（若正文最终决定纳入，见开放项 T-08）的具体实现与评价指标同样置于本节，不在正文展开。

## M6. 量子化学验证与路径组装

- TS 猜测阶梯、优化、频率、IRC 和端点判读。
- 路径级几何链式组装、证据打包和独立自检。
- 完整参数、验收标准历史与逐步证据表置于扩展数据。
- 正负对照设计与实测（`evidence/controls.md`）：交付 TS 天花板；水中继在现行验收标准下的拒收；from-SMILES 复现战役的通过率与算力设置。明确对照度量的是判据分辨力，不是模块消融。

## M7. C1/C2 验证接口、饱和统计与展示曲线（服务 §3.4–§4）

- **C1**：修复重放 + 迁移重放协议；其余资产快照固定；taxonomy 版本固定。
- **C2**：前瞻任务集暴露协议；最终资产 vs 初始资产；两侧冻结 Reflect；预算单位（核时 + attempt 数）。
- **饱和统计（D-28）**：三类机制诊断面板；K=3；ε=5%；诊断面板 ≠ C2 held-out；attempt 列表预注册填空。
- 观察性累计曲线的日期来源与证据等级（判决时间戳 / 交付包作业时间 / 资产出现估计）；ADR 0002（否决 transcript 虚频定日）。
- 更新后复用范围陈述规则（§3.0）；with/without 支持性协议（不替代 C1/C2）。
- **投稿前以升钉输出为准**，单一 STRICT 口径锁定数字。
